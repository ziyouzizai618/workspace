[title] git常用命令
新建仓库
git init初始化仓库，可以发现当前目录下多了一个.git的目录，这个目录是Git来跟踪管理版本库的
代码提交
git add . 提交修改过或新增的文件到暂存区
git add <file> 提交指定的修改过或新增的文件到暂存区
git commit -m "commit info" 将暂存区的文件提交到本地仓库中
创建和合并分支
git checkout -b dev创建一个新的分支：dev，并且会切换到dev分支
git branch dev，新建分支是新建指针,指向当前commit
git checkout dev切换到dev分支
查询配置信息
git config --list 列出当前配置
常用查看指令
git status 查看仓库当前的状态
bug分支
git还提供了一个stash功能，可以把当前工作现场“储藏”起来，等以后恢复现场后继续工作
git stash保存工作现场
git stash list 查看工作现场
git stash apply恢复工作现场，但是恢复后，stash内容并不删除，有多个工作现场时可以git stash apply stash@{0}恢复特定的现场
git stash drop删除stash的内容
git stash pop恢复的同时也把stas内容删除

NOTE: 测试遵循了 Arrange-Act-Assert (AAA) 模式，这是提高可读性和维护性的好习惯：
NOTE: Arrange：设置初始状态 (std::unique_ptr<Executor> executor(Executor::NewExecutor({0, 0, 'E'}));)

NOTE: std::tie 的使用使得 Pose 类的比较操作变得非常简洁和高效。这是一个很好的实践，展示了如何利用 C++ 标准库中的工具来简化代码和提高可读性。

[title] 如何使用gtest编写测试用例
[body] 测试用例文件命名
[body] 文件名通常命名为 xxxTest.cpp，例如 ExecutorTest.cpp
[body] 测试套件与测试函数
[body] TEST（测试套件名，测试函数名）：这是一个宏，用于定义一个测试函数，分为两部分：
[body] 测试套件名：表示一组相关的测试函数的名字，通常与文件名保持一致，例如ExecutorTest
[body] 测试函数名：表示单个测试函数的名字，一个测试用例一个测试函数
[body] 断言
[body] 断言宏：ASSERT_EQ （val1，val2）：用于断言 val1 和 val2 是否相等，如果不相等，则会终止当前测试函数的执行，并报告错误信息。

void ExecutorImpl::Execute(const std::string& commands) noexcept
{
for (const auto cmd : commands) {
if (cmd == 'M') {
if (pose.heading == 'E') {
++pose.x;
} else if (pose.heading == 'W') {
--pose.x;
} else if (pose.heading == 'N') {
++pose.y;
} else if (pose.heading == 'S') {
--pose.y;
}
}
}
}
